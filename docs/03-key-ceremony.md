# 3. Key ceremony

The cryptography is rarely the hardest part. Knowing **which public key truly belongs to which person**, and keeping the matching private key safe, is the real ceremony.

## Generate locally

Each person generates their own two key pairs on their own device, using a local tool they have inspected. Private keys are not generated by a correspondent, a cloud service or a web page supplied with an envelope.

## Exchange public keys and pin fingerprints

A public key can be shared openly, but openness does not prove ownership. An attacker who can substitute a public key can redirect future envelopes to themselves.

Therefore:

1. Exchange the public keys.
2. Compute each key's fingerprint independently.
3. Compare the fingerprints through a separate trusted channel — a voice call, an in-person check, or another route not controlled by the same channel being tested.
4. Record the pinned fingerprints with the key's purpose and creation date.

Only after pinning should an envelope be sealed.

## Keep private keys at home

A private key should have one deliberate home and, where appropriate, one deliberate backup method. It must never be:

- committed to Git;
- uploaded with an envelope;
- pasted into chat, email or a document;
- typed into a received HTML page;
- generated or stored by the other participant.

## Rotation and retirement

Old public keys should be archived rather than deleted. Old signatures still need verification, and old envelopes remain addressed to old encryption keys.

When a key is replaced:

1. Generate the new pair locally.
2. Pin its fingerprint through the trusted channel.
3. Mark the old public key as retired, with the date and reason.
4. Keep the old public key available for verification history.

## Loss is different from theft

- **Lost and known destroyed:** retire the key. Future work moves to a new key. Envelopes addressed to a lost encryption key cannot be recovered unless the sender still has the original and can reseal it.
- **Possibly copied:** treat the key as compromised. Announce it, retire it, and distrust dependent signatures from the earliest plausible compromise time.

There is no password reset for a private key. That absence is not a missing feature; it is the source of the guarantee.
